# Cecilia 桌宠系统诊断与重构方案（待确认）

日期：2026-10-14。当前阶段：研究、复现和设计已完成；尚未修改或安装修复。用户补充的“三套舞蹈与大量互动未实现”已作为核心问题纳入范围。

## 1. 结论与证据边界

当前版本未达到“明确的 2.5D、动漫动作质量、120fps、完整舞蹈和互动、画面零错误”的综合要求。失败涉及素材、动作内容、渲染、调度和验收方法，不能通过再调一次播放速度解决。

本次已通读安装包顶层 21 个 Python / JavaScript 源文件，核对 manifest、83 个资源头、历史动作参考与未安装候选的进度。生成 HTML 的内嵌 manifest 是数据，播放逻辑位于已读取的 preview-control.js。安装包自带文档中的旧“已通过”结论，仅作为历史声明核对，不作为当前验收事实。

证据分为四级：**原生实测**（当前桌宠及显示器）；**独立复现**（独立浏览器运行当前安装的相同着色器与取帧函数）；**源码确认**；**待实测**。独立复现包含 60 个服装／动作组合，每个九个阶段，共 540 个阶段采样。它们证明对应阶段的渲染行为，不等于 60 段动作都已完成连续原生验收。

未更改安装包源文件、manifest 或素材。没有强制选择动作、修改宿主任务属性、注入旧探针、重启客户端或改变显示器设置。源文件前后哈希一致。测试辅助浏览器与 HTTP 服务已退出。

## 5. 三套舞蹈和全部互动如何重新算完成

动作详表见 [动作实现与验收清单](动作实现与验收清单.md)。当前 20 个动作条目乘三套服装形成 60 个组合，其中有 9 个舞蹈组合、12 个双人场景组合。16 个 look 条目另列为朝向覆盖，不能当作 16 段丰富互动。

三舞蹈必须有独立编舞、真实关键姿势和中间帧，保留完整进入、表演、返回中性、循环衔接。OP 使用已存参考：42.876–45.796 秒的低手摆动→侧转→背面→回正→斜上举臂；不可用前视角轻摆冒充背面转身。小手摇摆与踮脚拍手分别具有自身的动作节奏和足部支点。

每段互动登记：触发条件、情绪／意图、参与者、预备、主要回应、重叠跟随、收尾、安全打断点、素材与实际原生视频。点击、拖住、放下、连续点击和取消事件也必须有完整回应。两人互动必须有双方参与，拉袖的手与布料须持续接触。历史记录里尚未能确认具体内容的新增互动，记录为需明确设计，不自行改成无关动作来凑数量。

核心可借鉴方法是完整动作资源、异步准备后交换、失效请求隔离、事件结束驱动和时间驱动的窗口运动。抽查的待机、下蹲、舞蹈 WebM 是 VP9、640×360、24fps，带 ALPHA_MODE=1；本地资源目录共有 106 个 WebM。它提供了“动作片段已经做完整，再交给播放器呈现”的方法参考。

源码没有证明它已达稳定 120fps，也没有提供本任务所需的完整 2.5D 制作体系。它的 opacity 过渡可能产生双轮廓，不能直接套用到本角色。其 loadeddata 就绪检查也需补足本项目对第一帧可呈现、接姿态、遮挡和色彩边缘的验收。未安装或运行参考项目，研究结论来自源码和本地媒体元数据抽查。

## 7. 建议重做的模块与新设计

### 7.1 重做动作素材与时间轴

理由：现有四个姿势无法补出 OP 完整背身和斜上举臂；同一立绘的摆臂无法补出五种不同情绪；输入里已经有裁头和错误比例。继续增加光流、播放倍率和固定身体补片，会加重遮挡与拓扑矛盾。

设计：按动画制作流程形成动作脚本→参考／节拍表→关键姿势→中间帧→清线和色彩→跟随动作→透明／深度资源→源素材审查→打包。以 24fps 时间表编排，允许拍 2、强调动作拍 1、适当停顿。每一拍有明确内容，120Hz 负责呈现和必要的小幅次要运动，不强制把每个 cel 都平滑扭成另一个画面。

大转身、脸／手表情和接触动作使用完整人物姿势。辅助网格只处理小幅发丝／布料／呼吸变化，不能再次接管整个头脸、肩部和手臂。完成一个端到端试作后，再扩到三套服装和所有动作。

### 7.2 重做动画调度与过渡

理由：当前任务长期抢占、300ms 点击窗口和资源准备后的硬切，源于播放契约本身。单独延长某个计时器不能保证完整回应和衔接。

设计：分开日常动作、任务提示、输入回应、双人场景、换装与 transition；显式优先级、动作结束、可打断点、恢复位置和姿态兼容规则。预加载预测不改变真实动作时间。双人接触时只在允许边界打断；紧急中断须有回接动画。

### 7.3 重构渲染提交与资源准备

理由：当前把 draw 次数当成 fps、在同一主线程进行资源管理、仅用状态名称定位时间，并以大量 120Hz 数据展开。重构要使节拍、模拟、素材和呈现可以各自核验。

设计：由单调时钟给出动作时间；紧凑时间轴保留关键姿势和曝光时长；独立受限队列解码／上传，缓存当前和下一动作；第一帧确认可呈现后原子提交。统一透明与颜色空间；运行时避免每帧字符串比较和大对象重建。实际测量是否需要 worker、减少 preserveDrawingBuffer 或改变图集尺寸，按性能结果选择，不盲目重写。

2.5D 增加可控的前后层、逐视角透视与遮挡数据、角色法线／深度辅助、环境光与接地阴影。保持现有 Q 版身份、三套服装和原生窗口路线，现阶段不迁移 Live2D 或完整 3D 引擎。

## 8. 严格逐步实施顺序

| 步骤 | 具体工作 | 本步交付与必须展示的证据 | 进入下一步条件 |
|---|---|---|---|
| S0 当前 | 报告、根因、基线与设计 | 本报告、60 组阶段图、原生采样、参考研究 | 用户确认本报告和新方案 |
| S1 | 候选目录备份；修好测量隔离与呈现统计 | 123→223 失败用例变绿；实际回调／呈现记录；回滚预检 | 测量可信，现场恢复正常 |
| S2 | 先逐项修 D01/D02 输入素材，再修 D03/D04/D05 画面路径 | 每项分别给前后正常尺寸视频、失败帧、原生复测与交互回归 | 本项通过后才开始下一项，不只跑单元测试 |
| S3 | 一个具有清晰体积感的待机／转身／接地试作 | 正侧背、视差、阴影、呼吸、跟随；用户可直接看效果 | 2.5D 视觉与制作流程通过，不批量复制失败方案 |
| S4 | OP、小手摇摆、踮脚拍手逐个重做 | 每舞种关键姿势表、完整周期视频、原生两轮；之后逐服装扩展 | 每个舞种独立通过，最终九组均通过 |
| S5 | 按动作清单逐条制作单人、点击拖放与双人互动 | 各条完整触发→回应→收尾的原生视频；接触与表情检查 | 全部既定动作通过；没有只登记名字的“完成项” |
| S6 | 过渡与任务联动、换装、单／双人布局 | 状态切换矩阵、长任务恢复日常、真实鼠标与边缘布局视频 | 不瞬移、不截断，不破坏现有功能 |
| S7 | 120Hz 性能、DPI、朝向、透明与长时间回归 | 实际高刷单／双人长跑、混合 DPI／多屏录屏、实际桌面效果 | 全部验收格签署；缺设备或未测项目保持开放 |
| S8 | 安装、冷启动验证、最终修复报告 | 版本／文件哈希、每个问题的修改原因与验证、备份和恢复脚本 | 正式运行通过；不能把候选状态写成安装完成 |

在候选范围内可按用户确认的步骤自主推进；每完成一个问题，都先展示并运行验证，失败则留在该项。若进一步扩大整块重写或影响正常交互，再说明变化和理由。方案已经获得用户确认，现已进入 S2；逐项安装与未完成范围以《重构进度与验收账本》为准。

## 9. 功能保护与验收签署

保留原生宠物身份、拖拽、菜单、窗口置顶、透明、三套服装轮换、双人场景和用户当前选择。扩展画布继续 pointer-events:none，宿主控制窗口。输入分类、双人舞台尺寸与任务优先级属于明确的改动影响点，须逐项做真实交互回归。

| 最终验收项 | 当前状态 | 通过证据要求 |
|---|---|---|
| 明确的 2.5D | 未通过 | 正常桌面尺寸动作中段可见空间关系与体积；用户视觉确认 |
| 稳定可见 120fps | 未通过；诊断时60Hz，2026-10-14中断后复核为165Hz，支持120Hz模式 | 实际 ≥120Hz 显示器的合成呈现记录；复杂动作长跑 |
| 动画原理、活体待机 | 未通过 | 完整动作节奏、预备／跟随／回弹／呼吸视频 |
| 三套舞蹈及丰富互动 | 未通过 | 九个舞蹈组合与全部动作目录的完整原生触发和内容验收 |
| 所有切换连续 | 未通过 | 状态矩阵、打断／恢复和换装视频 |
| 画面零已知错误 | 未通过 | 当前 P0 全消除；全阶段与透明／DPI／朝向矩阵，发现问题继续登记 |
| 原有功能全部正常 | 本轮未改动；重构后待回归 | 真实拖拽／菜单／置顶／透明／启动测试 |
| 最终修复报告 | 尚未产生 | 修改内容、理由、运行证据、限制、安装版本逐项对应 |

“零错误”不能由有限采样证明任意设备与任意未来场景永不出错。执行上要求测试矩阵中零已知失败、所有报告过的问题都有实证修复；不把未测场景或错误素材遗漏包装成“全部通过”。
